# vpn-killswitch.sh — kill switch для VPN на macOS

Скрипт не даёт трафику уйти в интернет мимо VPN. Если VPN отвалился, интернет
просто пропадает, а не продолжает работать напрямую через провайдера с вашим
настоящим IP.

Работает на встроенном в macOS файрволе **pf** (Packet Filter). Включается и
выключается на лету, без перезагрузки.

## Быстрый старт

```bash
chmod +x vpn-killswitch.sh

# включить: 203.0.113.10 — IP вашего VPN-сервера
sudo ./vpn-killswitch.sh --start 203.0.113.10

# посмотреть состояние
sudo ./vpn-killswitch.sh --status

# выключить
sudo ./vpn-killswitch.sh --stop
```

Если запустить без `sudo`, скрипт сам перезапустится через `sudo` и спросит пароль.

## Установка как команды (чтобы не ходить в папку)

Один раз выполните в папке со скриптом:

```bash
sudo ./vpn-killswitch.sh --install
```

Скрипт скопирует себя в `/usr/local/bin/vpn-killswitch`. Эта папка по умолчанию
есть в `PATH`: это список папок, в которых терминал ищет команды (на macOS он
задаётся в файле `/etc/paths`). После этого скрипт запускается из любой папки,
уже без `./` и `.sh`:

```bash
sudo vpn-killswitch --start 203.0.113.10
sudo vpn-killswitch --stop
sudo vpn-killswitch --status
```

Что важно знать:
- Устанавливается **копия**. Если вы поменяли скрипт в папке, повторите
  `sudo ./vpn-killswitch.sh --install`, чтобы обновить установленную версию.
- Копия принадлежит root, и обычный пользователь не может её изменить. Скрипт
  запускается через `sudo`, поэтому подменить его не должна суметь ни одна
  программа без пароля администратора.
- Удаление: `sudo vpn-killswitch --uninstall`. Если kill switch в этот момент
  включён, скрипт откажется удаляться и попросит сначала выполнить `--stop`,
  чтобы вы не остались без интернета и без команды, которая его вернёт.

## Параметры

| Флаг | Что делает |
|---|---|
| `--start <IP> [IP2 ...]` | Включает kill switch. IP-адресов может быть несколько, через пробел или запятую: `--start 1.2.3.4,5.6.7.8` |
| `--allow-lan` | Только вместе с `--start`: дополнительно разрешает локальную сеть (роутер, принтеры, NAS, AirDrop) |
| `--stop` | Выключает kill switch, всё возвращается как было |
| `--status` | Показывает, включён ли kill switch, и действующие правила |
| `--install` | Устанавливает скрипт как команду `vpn-killswitch` (см. выше) |
| `--uninstall` | Удаляет установленную команду |
| `-h`, `--help` | Справка |

Повторный `--start` с другими IP просто обновит правила, выключать перед этим не нужно.

## Что пропускается, а что блокируется

Когда kill switch включён, разрешено только следующее:

1. **Всё, что идёт через VPN-туннель** (интерфейсы `utun*`, `ipsec*`, `ppp*`, `tun*`).
   Это и есть ваш обычный интернет: сайты, мессенджеры и т.д. Пока VPN работает,
   всё ходит как обычно.
2. **Пакеты к IP VPN-сервера и от него**, по любому протоколу. Без этого VPN не
   смог бы подключиться: зашифрованный туннель нужно сначала до этого сервера
   проложить.
3. **Loopback (`lo0`)**: обмен данными программ внутри самого компьютера
   (`localhost`, `127.0.0.1`). Наружу он не выходит.
4. **DHCP**: компьютер получает от роутера свой адрес в домашней сети. Без него
   через какое-то время Wi-Fi потеряет адрес, и VPN не сможет переподключиться.
5. **Локальная сеть**, только с `--allow-lan`: адреса `192.168.x.x`, `10.x.x.x`,
   `172.16–31.x.x`, `169.254.x.x`, а также multicast/broadcast (по ним работают
   Bonjour, AirPlay, поиск принтеров).

Всё остальное блокируется:
- исходящий трафик отклоняется сразу, поэтому программы быстро получают ошибку,
  а не висят по таймауту;
- входящий трафик молча отбрасывается;
- IPv6 мимо туннеля тоже блокируется, так что через него ничего не утечёт.

### Простыми словами

В интернет можно выйти только **внутри VPN-туннеля**. Напрямую (не через туннель)
можно говорить только с самим VPN-сервером, чтобы этот туннель установить.

Важно: «трафик только через указанный IP» не значит, что вы можете открыть
только этот IP. Пока VPN подключён, доступен весь интернет, просто всё упаковано
в туннель до этого сервера. Если VPN отвалился, туннеля нет, и наружу пройдут
только попытки снова подключиться к серверу.

### А DHCP — это локальное?

Да. DHCP — это когда при подключении к Wi-Fi компьютер кричит на всю домашнюю
сеть «дайте мне адрес», а роутер отвечает «бери 192.168.1.23». Этот обмен
происходит только между компьютером и роутером и в интернет не уходит. Разрешено
только это: зайти в веб-интерфейс роутера или напечатать на принтере без
`--allow-lan` не получится.

### А DNS?

DNS (перевод имён сайтов в IP) не разрешён отдельно. Пока VPN работает, DNS-запросы
идут через туннель, как и всё остальное. Пока VPN выключен, DNS не работает, и
именно поэтому скрипту нужен **IP** сервера, а не доменное имя: без VPN
узнать IP по имени не получится.

Если в настройках VPN сервер указан именем (например, `nl1.example-vpn.com`),
узнайте его IP заранее, **до** включения kill switch:

```bash
dig +short nl1.example-vpn.com
```

Если адресов несколько, передайте все. Если IP у провайдера VPN часто меняется,
kill switch придётся перезапускать с новыми адресами.

## Как проверить, что работает

1. Подключите VPN и включите kill switch:
   ```bash
   sudo ./vpn-killswitch.sh --start <IP_сервера>
   ```
2. Проверьте, что интернет есть и IP — VPN-ный:
   ```bash
   curl -m 5 https://ifconfig.me
   ```
3. Отключите VPN и повторите тот же `curl`. Он должен сразу завершиться ошибкой.
4. Подключите VPN обратно: интернет должен вернуться без каких-либо действий со
   скриптом.
5. Выключите kill switch: `sudo ./vpn-killswitch.sh --stop`.

## Как это устроено

- **pf** — файрвол, встроенный в macOS (пришёл из OpenBSD). По умолчанию он
  выключен, а правила управляются утилитой `pfctl`.
- Скрипт **не трогает `/etc/pf.conf`**. Правила загружаются в отдельный раздел
  (anchor) `com.apple/000.vpn_killswitch`. Системный конфиг и так проверяет все
  разделы внутри `com.apple/`, поэтому наши правила начинают действовать сразу.
  Префикс `000.` нужен, чтобы они проверялись раньше системных.
- pf включается командой `pfctl -E`, которая выдаёт «токен». `--stop` снимает
  только этот токен: если pf нужен ещё чему-то в системе (например, общему доступу
  к интернету), он останется включённым, иначе выключится.
- Правила работают без отслеживания соединений (`no state`). Поэтому соединения,
  уже открытые через VPN, при включении kill switch не рвутся.
- При `--start` сбрасывается таблица состояний pf, чтобы соединения, открытые
  мимо VPN ещё до включения, не продолжили работать.
- Служебные файлы (токен и сгенерированные правила) лежат в `/var/run/vpn-killswitch/`.
  Посмотреть правила можно так: `sudo cat /var/run/vpn-killswitch/rules.conf`.

## Ограничения

- **После перезагрузки kill switch выключен.** Правила pf хранятся только в памяти.
  Если нужно автовключение при загрузке, можно сделать LaunchDaemon.
- **Разрешён любой `utun`-интерфейс.** macOS сама создаёт несколько `utun`
  (`utun0`–`utun5` и т.п.) для iCloud и других служб, и трафик через них тоже
  будет пропущен. Это стандартный подход для kill switch, но не самый строгий.
- **Сторонние файрволы на pf** (например, Murus) или VPN-клиенты со своим kill
  switch могут конфликтовать с этим скриптом. Лучше использовать что-то одно.
- Если VPN-клиенту нужно что-то ещё помимо IP сервера (например, отдельный сервер
  авторизации по другому адресу), добавьте этот IP в `--start` тоже.

## Если что-то пошло не так

Если интернет пропал и не возвращается, выключите kill switch:

```bash
sudo ./vpn-killswitch.sh --stop
```

Если и это не помогло, сбросьте pf на системные настройки вручную:

```bash
sudo pfctl -a com.apple/000.vpn_killswitch -F rules
```

И в крайнем случае просто перезагрузите Mac: после перезагрузки правил скрипта
уже не будет.
