# vpn-killswitch для Windows

Тот же kill switch, что и для macOS (см. [README.md](README.md)), но для Windows 10/11.
Если VPN отвалился, интернет пропадает, а не продолжает работать напрямую через
провайдера с вашим настоящим IP.

Работает на встроенном **брандмауэре Windows** (Windows Defender Firewall).
Включается и выключается на лету, без перезагрузки.

Файлы:
- `vpn-killswitch.ps1` — сам скрипт (PowerShell);
- `vpn-killswitch.cmd` — запускалка, чтобы не возиться с настройками PowerShell.

Обе части должны лежать в одной папке.

## Быстрый старт

Откройте обычную командную строку (`cmd`) или PowerShell в папке со скриптом:

```bat
:: включить: 203.0.113.10 — IP вашего VPN-сервера
vpn-killswitch.cmd --start 203.0.113.10

:: посмотреть состояние
vpn-killswitch.cmd --status

:: выключить
vpn-killswitch.cmd --stop
```

Скрипту нужны права администратора. Если терминал запущен без них, Windows
покажет окно UAC («Разрешить этому приложению вносить изменения?»), и скрипт
выполнится в новом окне. Окно не закроется, пока вы не нажмёте Enter, чтобы
можно было прочитать результат.

Можно запускать и сам `.ps1` из PowerShell, открытого от администратора:

```powershell
.\vpn-killswitch.ps1 --start 203.0.113.10
```

Если PowerShell пишет, что выполнение скриптов запрещено, используйте
`vpn-killswitch.cmd`: он запускает скрипт с разрешением только на этот раз и
системную настройку не меняет.

## Установка как команды (чтобы не ходить в папку)

Один раз выполните в папке со скриптом:

```bat
vpn-killswitch.cmd --install
```

Что произойдёт:
- скрипт скопируется в `C:\Program Files\vpn-killswitch\`;
- рядом, в папке `bin`, появится запускалка `vpn-killswitch.cmd`;
- папка `bin` добавится в системную переменную `PATH`: это список папок, в
  которых Windows ищет команды.

После этого **откройте новое окно** терминала (уже открытые окна про новый
`PATH` не знают). Скрипт запускается из любой папки, в `cmd` и в PowerShell:

```bat
vpn-killswitch --start 203.0.113.10
vpn-killswitch --stop
vpn-killswitch --status
```

Что важно знать:
- Устанавливается **копия**. Если вы поменяли скрипт в папке, повторите
  `vpn-killswitch.cmd --install` из этой папки, чтобы обновить установленную версию.
- В `PATH` попадает только `.cmd`, а `.ps1` лежит уровнем выше. Иначе PowerShell
  находил бы `.ps1` первым и упирался в запрет на выполнение скриптов.
- `Program Files` доступна для записи только администраторам. Скрипт запускается
  с правами администратора, поэтому подменить его не должна суметь ни одна
  обычная программа.
- Удаление: `vpn-killswitch --uninstall`. Папка удалится, запись из `PATH` тоже.
  Если kill switch в этот момент включён, скрипт откажется удаляться и попросит
  сначала выполнить `--stop`.

Ещё варианты, если не хочется ничего устанавливать:
- создать ярлык на рабочем столе: правый клик → «Создать» → «Ярлык», объект
  `"C:\путь\к\vpn-killswitch.cmd" --start 203.0.113.10`. Второй такой же ярлык
  с `--stop` даст две «кнопки» включения и выключения;
- открыть терминал сразу в папке: в Проводнике ввести `cmd` в адресной строке и
  нажать Enter.

## Параметры

Те же, что и в версии для macOS:

| Флаг | Что делает |
|---|---|
| `--start <IP> [IP2 ...]` | Включает kill switch. IP-адресов может быть несколько, через пробел или запятую: `--start 1.2.3.4,5.6.7.8` |
| `--allow-lan` | Только вместе с `--start`: дополнительно разрешает локальную сеть (роутер, принтеры, NAS) |
| `--stop` | Выключает kill switch, всё возвращается как было |
| `--status` | Показывает, включён ли kill switch, разрешённые IP, адаптеры и правила |
| `--install` | Устанавливает скрипт как команду `vpn-killswitch` (см. выше) |
| `--uninstall` | Удаляет установленную команду |
| `-h`, `--help` | Справка |

Флаги можно писать и в стиле Windows: `-start`, `/start`, `/stop`.
Повторный `--start` с другими IP просто обновит правила.

## Что пропускается, а что блокируется

Логика та же, что на macOS. Разрешено:

1. **Всё, что идёт через VPN-туннель.** Правила вешаются только на физические
   адаптеры (Wi-Fi, Ethernet), а VPN создаёт свой виртуальный адаптер (TAP,
   Wintun, WireGuard, встроенный VPN Windows). Его правила не трогают.
2. **Трафик к IP VPN-сервера и от него**, по любому протоколу, чтобы туннель мог
   подключиться.
3. **Loopback** (`localhost`, `127.0.0.1`): брандмауэр Windows его вообще не
   фильтрует.
4. **DHCP**: получение адреса от роутера, это локальный обмен в пределах вашей сети.
5. **Локальная сеть**, только с `--allow-lan`.

Всё остальное на физических адаптерах блокируется: TCP, UDP, ICMP (ping), в обе
стороны, для IPv4 и IPv6.

## Как это устроено

### Брандмауэр Windows и WFP

В Windows за фильтрацию трафика отвечает **WFP (Windows Filtering Platform)**:
механизм внутри ядра, через который проходит каждое соединение. Брандмауэр
Windows — понятная надстройка над WFP: вы задаёте правила, он превращает их в
фильтры WFP. Работает он как служба `mpssvc`.

Правило брандмауэра описывает: направление (входящее/исходящее), действие
(разрешить/блокировать), протокол, порты, удалённые адреса и сетевые адаптеры.

Главная особенность, на которой держится скрипт: **в брандмауэре Windows
блокирующее правило всегда сильнее разрешающего**, порядок значения не имеет.
Поэтому скрипт создаёт только блокирующие правила. Какие бы разрешения ни
наставили программы при установке, мимо VPN они не пропустят.

### Почему правил несколько и откуда «странные» диапазоны адресов

В pf на macOS можно написать «разрешить к IP сервера, а остальное запретить».
Брандмауэр Windows так не умеет: блокировка сильнее всего, а написать «блокировать
всё, кроме X» нельзя.

Поэтому скрипт сам вычисляет **дополнение**: список диапазонов, который покрывает
все адреса интернета, кроме разрешённых. Например, для сервера `203.0.113.10`
получится:

```
0.0.0.0-203.0.113.9
203.0.113.11-255.255.255.255
```

То есть «всё до сервера и всё после него». С `--allow-lan` из этого списка
вырезаются ещё и диапазоны локальной сети. Для IPv6 то же самое.

Порт DHCP вырезается так же: UDP блокируется на всех удалённых портах, кроме 67
(порт DHCP-сервера).

В итоге создаётся до 8 правил (`исходящие/входящие` × `TCP/UDP/ICMPv4/ICMPv6`), все
в группе **«VPN Killswitch»**. Их видно в графической оснастке: `Win + R` →
`wf.msc` → «Правила для исходящих/входящих подключений».

### Шаги `--start`

1. Проверяет, что служба брандмауэра (`mpssvc`) работает.
2. Находит физические адаптеры (`Get-NetAdapter -Physical`), исключая всё, что
   похоже на VPN (по названию: TAP, Wintun, WireGuard, VPN…).
3. Вычисляет диапазоны для блокировки.
4. Удаляет старые правила группы «VPN Killswitch» (если были) и создаёт новые.
   Если что-то пошло не так посередине, созданные правила удаляются, чтобы не
   оставить систему наполовину настроенной.
5. Если брандмауэр Windows был **выключен** в каком-то профиле (Доменная / Частная /
   Общедоступная сеть), включает его. Без этого правила просто не действуют.
   Скрипт запоминает, что включил его сам.
6. Сохраняет состояние в `C:\ProgramData\vpn-killswitch\state.json`.

Уже открытые соединения мимо VPN тоже обрываются: при изменении правил Windows
заново проверяет существующие соединения.

### Шаги `--stop`

1. Удаляет все правила группы «VPN Killswitch».
2. Если на `--start` скрипт включал брандмауэр в каких-то профилях, выключает его
   обратно, как было.
3. Удаляет папку состояния.

## Отличия от версии для macOS

| | macOS | Windows |
|---|---|---|
| Механизм | pf, правила в anchor `com.apple/000.vpn_killswitch` | брандмауэр Windows (WFP), группа правил «VPN Killswitch» |
| Как отделяется VPN | разрешаем туннельные интерфейсы `utun*` и т.п. | блокируем физические адаптеры, туннели не трогаем |
| **После перезагрузки** | **выключен** (правила pf только в памяти) | **остаётся включённым** (правила брандмауэра хранятся постоянно) |
| Права | `sudo` | администратор (UAC) |

Сохранение после перезагрузки на Windows — скорее плюс для kill switch: компьютер
не начнёт «светить» настоящий IP, пока VPN ещё не подключился после загрузки.
Просто помните, что выключать его нужно явно, через `--stop`.

## DNS

Пока VPN выключен, DNS не работает. Поэтому скрипту нужен **IP** сервера, а не
доменное имя. Если в настройках VPN указано имя, узнайте IP заранее, **до**
включения kill switch:

```bat
nslookup nl1.example-vpn.com
```

Если адресов несколько, передайте все.

Осторожно с `--allow-lan`: DNS-запросы к роутеру (например, `192.168.1.1`) тогда
тоже разрешены. Windows иногда шлёт DNS-запросы сразу через все адаптеры, и часть
из них может уйти к роутеру, а от него к провайдеру. Это не утечка трафика, но
провайдер может увидеть, какие сайты вы открываете. Если это важно, не
используйте `--allow-lan`. (То же самое относится и к версии для macOS.)

## Как проверить, что работает

1. Подключите VPN и включите kill switch:
   ```bat
   vpn-killswitch.cmd --start <IP_сервера>
   ```
2. Проверьте, что интернет есть и IP — VPN-ный (`curl` встроен в Windows 10/11):
   ```bat
   curl.exe -m 5 https://ifconfig.me
   ```
3. Отключите VPN и повторите тот же `curl`. Он должен завершиться ошибкой.
4. Подключите VPN обратно: интернет должен вернуться без каких-либо действий со
   скриптом.
5. Выключите kill switch: `vpn-killswitch.cmd --stop`.

Если на шаге 3 интернет всё ещё работает, запустите `--status` и проверьте строку
«Блокируемые адаптеры»: там должен быть ваш Wi-Fi или Ethernet.

## Ограничения

- **Новые адаптеры.** Правила привязаны к адаптерам, которые были на момент
  `--start`. Если потом подключить USB-модем, телефон в режиме модема или новую
  сетевую карту, запустите `--start` ещё раз.
- **Hyper-V с внешним коммутатором.** В этом случае интернет идёт через
  виртуальный адаптер `vEthernet (...)`, который скрипт не считает физическим, и
  защита не сработает. (WSL2 и Docker Desktop по умолчанию на это не влияют.)
- **Сторонние файрволы и антивирусы** (Kaspersky, ESET, Norton и др.) часто
  отключают брандмауэр Windows и ставят свой. Тогда скрипт сообщит, что служба
  `mpssvc` не запущена. Нужно либо вернуть брандмауэр Windows, либо настраивать
  kill switch в стороннем файрволе.
- **Рабочие компьютеры в домене.** Групповая политика может запрещать локальные
  правила брандмауэра. Тогда правила создадутся, но действовать не будут.
- **Редкие протоколы.** Блокируются TCP, UDP и ICMP: это практически весь
  трафик обычных программ. Экзотические протоколы (GRE, SCTP и т.п.) мимо VPN не
  блокируются.
- **Встроенные kill switch'и.** Многие VPN-клиенты (официальный WireGuard с
  «Block untunneled traffic», клиенты коммерческих VPN) умеют то же самое на уровне
  WFP. Если такой есть, достаточно включить его. Вместе с этим скриптом они
  совместимы, но смысла держать оба мало.

## Если что-то пошло не так

Если интернет пропал и не возвращается, выключите kill switch:

```bat
vpn-killswitch.cmd --stop
```

Если скрипт недоступен, удалите правила вручную в PowerShell от администратора:

```powershell
Remove-NetFirewallRule -Group "VPN Killswitch"
```

Или через графику: `Win + R` → `wf.msc` → «Правила для исходящих подключений» и
«Правила для входящих подключений» → удалить правила, которые начинаются с
«VPN Killswitch».

Учтите: **перезагрузка здесь не поможет**, правила брандмауэра сохраняются.
